# OG 画像の設計と実装

## 基本方針: 「下地 PNG + 動的テキストだけ描く」

デザイン全体を canvas で再現しようとしない。デザイナーが作った OG 画像（1200×630）を
バリエーションごとに書き出し、**変わる部分（スコア・個数・名前など）だけを空けた下地**にして、
Lambda はそこに文字を描くだけにする。

- 見た目がデザインと一致しやすい（グラデーション・影・イラストは下地に焼き込まれている）
- Lambda の処理が軽い（下地デコード + 数文字の描画 + PNG エンコード）
- デザイン修正は下地の再書き出しで済み、コード変更が要らない

バリエーションの切り替えキー（診断タイプ・キャラ・ランクなど）を `variantId` とし、
`assets/og/{variantId}.png` に置く。キーは `schema.ts` の許可リストで照合する（パス生成に使うため）。

## 下地の作り方

1. デザインツールで OG 用フレーム（1200×630）をバリエーション数だけ用意してもらう
   - 動的部分には最大桁のダミー（`999,999,999` など）を入れておいてもらうと、箱のサイズが確定する
2. 書き出し方は 2 通り:
   - **動的テキストのレイヤーを非表示にして書き出す**（一番きれい。Figma REST なら非表示にした複製フレームを用意してもらう）
   - ダミー入りで書き出し、**動的領域を背景色で塗り潰す**スクリプトを書く（背景が単色/単純なグラデーションのとき）。
     塗り潰し矩形は `layout.ts` に定数で置き、隣接するラベルと干渉しないことを画像で確認する
3. 書き出しスクリプトは「期待するバリエーション一覧と完全一致しなければ既存ファイルを触らずエラー終了」にする。
   デザイン側のフレーム名の誤記はよくあるので、名前の接頭辞ではなく明確なトークンで判定する
4. 書き出し後、テストで「全バリエーションが揃っていて 1200×630」であることを確認する

Figma からの座標取得・書き出しは `figma-rest-api-coding` スキルが使える
（PNG は absoluteRenderBounds 基準で書き出される点に注意。フレーム単位で書き出せば 1200×630 になる）。

## レイアウト定数（render/layout.ts）

- 動的テキストごとに **箱（x, y, width, height）・揃え・スタイル**を持つ。箱はデザインのテキストボックスを写す
- 描画ロジックに数値を直書きしない。デザイン確定後の調整はこのファイルだけで済むようにする
- 縦位置: デザインツールの行ボックスとフォントの ascent/descent はずれるので、
  **キャップハイト（`measureText('0').actualBoundingBoxAscent`）を箱の中央に置く**のが数字では安定
  （Figma の「CAP_HEIGHT トリム」設定のテキストなら、箱の下端 = ベースライン）
- 最大桁で箱からはみ出す場合だけ比例縮小（`minFontSizePx` を下限に）
- 縁取り（Figma の OUTSIDE ストローク）: `lineWidth = 太さ × 2` で stroke → 上から fill
- 右揃え + letterSpacing: canvas は末尾の字間も幅に含めるので、その分 x を右へずらす
- グラデーション塗りは箱の上下を基準に `createLinearGradient`。ハードエッジは `[0.4999, A], [0.5, B]`

## フォント

- Lambda にシステムフォントは期待できない。**TTF/OTF を `assets/fonts/` に同梱**し
  `GlobalFonts.registerFromPath` で登録。登録失敗は throw（黙って既定フォントで描かせない）
- 登録は初回描画時に 1 回（モジュール読み込み時にやると、フォント未配置で healthz まで落ちる）
- ライセンス確認（Google Fonts の OFL 等は同梱可）
- 日本語はサイズが大きいので**使う文字だけサブセット化**（`pyftsubset` 等）。
  ユーザー入力の名前など任意文字を描くならフルセット + 容量増を受け入れる

## 画像フォーマット

- 1200×630。PNG で数百 KB 程度に収まるならそのまま。写真系で 1MB を超えるなら JPEG（品質 85 前後）
- X のカードは 5MB まで。LINE・Facebook も 1200×630 で問題ない

## テスト（test/draw.test.ts）

- 全バリエーション × 境界値（0・最大桁）で生成でき、サイズが 1200×630
- 生成画像を `temp/og-preview/` に書き出して**目視確認**（デザインの書き出しと並べて比較すると
  ずれが分かる。必要なら動的領域のピクセル差分で「描かれていること」を検証）
- 下地の選択が variantId ごとに一意

## 再生成

DynamoDB に `requestPayload` を保存しているので、レイアウトや下地を直した後に過去分を作り直せる。
ただし `u/*.png` は immutable 配信（ブラウザ・CDN に 1 年）で、**SNS 側のキャッシュは消せない**ので、
同じキーへの上書きでは確実には反映されない。基本は**公開前にレイアウトを確定させる**こと。

どうしても直す場合:
- 画像は**新しいキー**（例: `u/{id}-r2.png`）で書き出し、`u/{id}.html` の og:image をそのキーに向けて**HTML を上書き**する
  （HTML は max-age=60 なので CloudFront invalidation と合わせれば早く反映される）
- Lambda のテンプレート（share-redirect.html）を変えても、**保存済みの HTML は自動では変わらない**。
  既存分に反映したいなら上と同じく Query → HTML 再生成 → 上書きのスクリプトを書く
- X などは URL 単位でカードをキャッシュするため、既に投稿済みのカードは変わらないと思っておく
