# 非プログラマー向けの制作管理画面

## 仕様作成時の必須成果物

シナリオ、レベルデザイン、会話内容、フラグと条件・処理を、プログラムスキルのない制作者が画面から作成・入力・編集できるようにする。ゲーム機能と同時に編集項目・操作・保存先・検証方法を仕様化する。「後で管理画面を用意する」という未定義のタスクだけで済ませない。

Godotの `EditorPlugin` による専用管理画面を基本とし、必要なら2D/3Dビューポートと連携する。制作者にGDScript、JSON、`.tres` の記述、Nodeパスや内部IDの暗記を求めない。標準Inspectorで内部Resourceを辿るだけの操作を管理画面の完成としない。

## 編集対象と操作

| 対象 | 管理画面でできること | 入力時に確認すること |
|---|---|---|
| シナリオ | 章・場面・イベントを作成、並べ替え、分岐接続、開始・終了条件を設定 | 到達不能、出口の欠落、無条件ループ、未登録の場面 |
| レベルデザイン | 素材パレットから配置、位置・向き・大きさを変更、入口・出口・操作対象・Triggerを配置、場面と結び付け | 必須入口、参照切れ、衝突・操作範囲の重なり、遷移先 |
| 会話 | 話者を選択、本文と複数行を編集、選択肢を追加・接続、表示条件と結果を設定、プレビュー | 空の必須項目、行き先なしの選択肢、失われた本文・接続 |
| フラグ | 表示名・説明・型・初期値・適用範囲・リセット契機を編集、使用箇所を検索 | 型違い、重複、未定義参照、削除の影響 |
| 条件・処理 | 「すべて / いずれか / 否定」、比較対象・演算子・値、フラグ変更・会話開始・移動等を選択 | 型に合う比較・値、実行順序、存在しない対象 |
| 登録と実行 | 新規データを本編へ登録、開始状態を選択、場面から試遊、実行状態を確認 | 保存忘れ、未登録データ、開始条件の不足 |

対象ゲームに存在しない機能のダミー画面は作らない。存在する制作対象の編集経路はすべて設け、追加機能もランタイムと管理画面を対応させて実装する。

## 画面仕様に記載する内容

各画面に「利用者の目的 / 入力項目と型 / 初期値 / 選択候補 / 説明文 / 入力制約 / 保存先 / 他画面への遷移 / プレビュー / エラーからの修正手順」を書く。ゲーム用語と読みやすい表示名を使う。

- 一覧、検索、絞り込み、新規作成、複製、編集、保存、削除を対象に応じて用意する。
- IDは自動発行し、参照は名前付きの選択UIから設定する。表示名を変えても参照を維持する。
- エラーは「対象・原因・直し方」を表示し、クリックで編集箇所へ移動できるようにする。
- 未保存状態、保存中、成功、失敗を明確にする。変更取消とUndo/Redoを設け、参照先の削除や破壊的変更では影響を表示する。
- 大量項目、長い本文、小さい画面でも入力・保存ボタンが届くようにする。キーボードフォーカスとスクロールを確認する。
- 管理画面も [画像生成から画面実装へ](screen-design.md) の手順でデザインを生成してから実装する。

## データとランタイムの契約

型付きResourceを制作データの正本とし、ゲームは管理画面が保存した同じ定義を読む。Resourceの型、ID、参照の更新規則を仕様化する。グラフ表示位置等の編集メタデータと、プレイ中のフラグ値等の実行状態は分離する。

保存前に全体を検証し、不正入力で一部だけ更新されることを防ぐ。再読込後も本文・順序・条件・接続を維持する。生成器を併用する場合は管理画面の編集を検出・保全し、再生成で消さない。

## 段階的な実装と受入

仕様段階で全制作対象の編集方法を定め、各機能の実装とともに必要な管理画面を完成させる。コアループではその一場面の編集、機能統合では新規場面の制作から本編登録までを通す。対象コンテンツの量産開始前に対応する編集経路を受け入れる。

代表的な受入経路:

1. 管理画面で新規場面とレベルを作り、入口・操作対象を配置する。
2. 話者・本文・選択肢を入力し、新規フラグとその条件・更新処理を設定する。
3. イベントと会話を配置対象に結び付け、本編へ登録する。
4. 入力ミスの検査結果から該当項目へ移動し、画面上で修正する。
5. 保存してエディターを閉じ、再読込して内容と接続が保たれることを確認する。
6. 指定した初期状態から起動し、製品の入力で操作して分岐・会話・フラグ・遷移を確認する。

この一連をコード・データファイルの直接編集なしで完了できること。実利用者による確認の有無はQA記録で区別する。利用マニュアルも同じ経路を画面名・入力例・実行結果付きで説明する。
